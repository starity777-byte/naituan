# 首次进入与资源提示

`loading.js` 负责媒体下载、Cache Storage 和网络提示。`splash.js` 只等待 `CORE_SPRITES` 的三张动作首帧（待机、开心、吃鱼，共约 57 KB），不再等待十二张完整动画（4.51 MB）。这些首帧在 `assets/posters/`，由 `tools/build-pose-posters.py` 从原动画提取，保留同一 503×402 画布和脚底位置。旧的 360×360 缩略图不能直接用在房间角色上。房间图片只经媒体缓存下载一次，在后台逐步显示。

点击交互先显示对应轻量姿势，完整动画下载成功后再播放和计时。进屋后只用一个低优先级队列预热部分常用动画，音乐仍在下载或有前台资源卡顿时暂停预热；未使用的睡觉、大动作和饰品逐帧图按需下载。隐藏的生活／自习页面不在进屋时下载动图和背景。音乐由真实点击解锁，下载、播放限制和失败会显示提示。缓存不可用时仍可从网络加载，不影响游戏存档。

开场结束时显式刷新房间交互，不依赖图片再次触发 load。堆纸箱复用主小屋的动作缓存；“完美”文字放在游戏层内，首次开心动画下载完成后再计算显示时间。`tools/verify-interactions.cjs` 检查同画布、首次／缓存后真实拖动，以及延迟动画下的首次完美反馈；设置 `NAITUAN_BASELINE=01e496c` 可复现修复前的失败。

访客提示区分设备离线、下载较慢、HTTP 404/410 资源缺失、HTTP 5xx 资源服务异常、浏览器音频限制和页面运行错误。普通连接失败无法判断故障在哪一端，提示会明确保留不确定性。Google Fonts 和统计脚本失败不显示为游戏故障。

媒体缓存按网址路径隔离，版本由 `loading.js` 的 `VERSION` 管理，下载地址附带同一版本参数。发布修改过的媒体时递增版本；修改脚本时也更新 `index.html` 中对应的版本参数。只缓存成功的媒体响应，不缓存页面和脚本，不修改 `naituan-house-v1` 等存档。

本地验证：启动静态预览后，设置 `PLAYWRIGHT_PATH` 为 Playwright 模块路径，运行 `node tools/verify-loading.cjs`。预览地址默认 `http://127.0.0.1:8775/`，可用 `NAITUAN_PREVIEW` 覆盖。浏览器验证包括首次进入、断开媒体网络后的缓存复用、存档保留、慢动画计时、断网恢复、资源错误分类和重试，以及运行错误提示。
